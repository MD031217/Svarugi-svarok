# Weld Defect API

Бэкенд на Python 3.13 и FastAPI для распознавания дефектов сварных швов.
Pydantic 2 описывает ответы и YOLO-разметку, Pydantic Settings читает настройки
из окружения и `.env`. Зависимости управляются Poetry 2.

## Локальный запуск

```bash
poetry env use python3.13
poetry install
cp .env.example .env
poetry run uvicorn app.main:app --reload
```

Poetry создаёт `.venv/` внутри проекта; прежний `venv/` не изменяется.
В PyCharm выберите интерпретатор `.venv/bin/python`.
Swagger: <http://127.0.0.1:8000/docs>, OpenAPI: `/openapi.json`.

**Состояние первоначальной настройки:** `poetry.lock` пока не создан: среда
исполнения не имеет доступа к PyPI. Первый `poetry install` на машине с сетью
разрешит зависимости, создаст lockfile и установит пакеты. Добавьте `poetry.lock`
в Git; в дальнейшем используйте `poetry sync`. До этого транзитивные версии
не зафиксированы. Не заменяйте lockfile пустым или вручную составленным файлом.

## Docker

```bash
docker compose up --build -d
docker compose logs -f api
curl http://127.0.0.1:8000/health
docker compose down
```

Образ использует Python 3.13, отдельную стадию установки зависимостей,
непривилегированного пользователя, один процесс Uvicorn и healthcheck.
Исходный датасет, презентация, локальные окружения и веса в образ не копируются.
`models/` монтируется только для чтения; настройки берутся из необязательного `.env`.
Нужен Docker Compose 2.24+ для `env_file.required`.

Dockerfile допускает первую сборку без lockfile и создаёт его внутри builder.
Для повторяемых установок сначала выполните `poetry lock` локально и сохраните
полученный файл: Docker автоматически использует его. Базовый образ закреплён
по ветке Python и Debian, но не по digest, поэтому системные пакеты могут обновляться.
В этой среде выполнена проверка Compose, но сборка/запуск образа не проверены:
доступ к Docker socket запрещён.

По умолчанию используется CPU. Этот образ не настраивает CUDA/GPU passthrough;
Linux-пакеты PyTorch из PyPI могут включать CUDA-зависимости и увеличивать образ.
`YOLO_DEVICE=mps` подходит только для локального запуска на поддерживаемом Mac,
а не для Linux-контейнера Docker Desktop.

## API и модели

| Метод и путь | Назначение |
| --- | --- |
| `GET /health` | Процесс API отвечает; наличие весов не проверяется |
| `GET /api/v1/classes` | Пять классов **исходного датасета** |
| `POST /api/v1/predictions` | JPEG/PNG → классы, confidence, bounding boxes и `labels_txt` |

Загрузка изображения — бинарное тело запроса, не multipart:

```bash
curl -X POST http://127.0.0.1:8000/api/v1/predictions \
  -H 'Content-Type: image/jpeg' \
  --data-binary '@dataset/1 (1).jpg'
```

До размещения весов API возвращает `503` на распознавание; `/health`, `/docs`
и справочник классов работают. Веса загружаются один раз при первом запросе.
На старте сервера нет автоматического скачивания или обучения модели.
Некорректное изображение даёт `400`, превышение размера — `413`, другой формат — `415`.
Учитывается EXIF-ориентация: размеры ответа и координаты относятся к повёрнутому изображению.
Предсказания не записываются поверх исходной разметки.

В зависимостях закреплён `ultralytics==8.4.215`. YOLO26, YOLO11 и YOLOv8 —
семейства моделей в одной библиотеке; одновременно устанавливать несколько
версий Python-пакета не нужно. Семейство выбирается файлом весов:

| Файл | Семейство | Назначение |
| --- | --- | --- |
| `yolo26n.pt` | YOLO26 nano | Базовый вариант для начала экспериментов |
| `yolo11n.pt` | YOLO11 nano | Сравнение с предыдущим семейством |
| `yolov8n.pt` | YOLOv8 nano | Ещё один базовый вариант для сравнения |
| `best.pt` | Дообученная модель | Распознавание пяти классов дефектов |

Например, скачать базовую модель (требуется сеть):

```bash
cd models
poetry run python -c 'from ultralytics import YOLO; YOLO("yolo26n.pt")'
cd ..
```

Затем задайте в `.env` `YOLO_MODEL=models/yolo26n.pt` и перезапустите API.
Для другой модели скачайте соответствующий файл и поменяйте `YOLO_MODEL`.
Принимайте только доверенные локальные `.pt`-веса.

**Базовые веса обучены на COCO, а не на дефектах сварки.** Их `class_id=0`
не означает `adj`. Ответ предсказания использует имена из весов, справочник
`/classes` — имена исходного датасета. Для получения `adj/int/geo/pro/non`
нужно дообучить detection-модель на датасете с указанным порядком классов
и положить полученный `best.pt` в `models/`.

`labels_txt` содержит по пять полей на объект; confidence возвращается
отдельно в JSON. Такие предсказания можно использовать как черновик разметки
после проверки человеком. Пустой `labels_txt` означает, что модель не нашла
объектов выше `YOLO_CONFIDENCE`; это не доказательство отсутствия дефектов.

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `APP_NAME` | `Weld Defect API` | Название в OpenAPI |
| `DEBUG` | `false` | Режим отладки |
| `YOLO_MODEL` | `models/best.pt` | Путь к detection-весам |
| `YOLO_DEVICE` | `cpu` | Устройство PyTorch |
| `YOLO_CONFIDENCE` | `0.25` | Порог уверенности, `(0, 1]` |
| `YOLO_IMAGE_SIZE` | `640` | Размер входа, кратный 32 |
| `MAX_UPLOAD_BYTES` | `10485760` | Максимум 10 MiB на запрос |
| `MAX_IMAGE_PIXELS` | `20000000` | Ограничение площади изображения |

Переменные окружения имеют приоритет над `.env`. После изменения настроек
или весов перезапустите процесс. В Docker пути задаются внутри контейнера.

## Датасет и обучение

Подробный разбор исходных файлов: [docs/dataset.md](docs/dataset.md).
Полный машинный отчёт: [docs/dataset-audit.json](docs/dataset-audit.json).

Повторить проверку без изменения исходников:

```bash
poetry run python -m scripts.audit_dataset dataset --output docs/dataset-audit.json
```

Проверяются пары файлов, классы, координаты, декодирование изображений,
пустые метки, повторяющиеся строки и SHA-256-дубликаты изображений.
Отдельно перечисляются одинаковые изображения с различающейся разметкой.
При ошибках разметки, повреждённых изображениях или неполных парах код выхода — 1.
Пустые метки допустимы и сами по себе ошибкой не считаются.

Для обучения сначала подготовьте `data/weld/images/{train,val,test}`
и соответствующие `data/weld/labels/{train,val,test}`, копируя пары JPG/TXT.
Шаблон YAML: `configs/dataset.example.yaml`. Исходный `dataset/` не изменялся,
разбиение на выборки автоматически не выполнялось. Делите по исходным видео
или сварным соединениям, чтобы соседние кадры не попадали в разные выборки.

После подготовки структуры, из корня проекта:

```bash
poetry run yolo detect train model=yolo26n.pt \
  data=configs/dataset.example.yaml epochs=100 imgsz=640 device=cpu \
  project=runs name=weld26
cp runs/weld26/weights/best.pt models/best.pt
```

Обучение не запускалось. CPU подходит для проверки, полноценное обучение
может занимать много времени. Для сравнения моделей используйте одинаковые
выборки и параметры, отдельное имя эксперимента и подходящее устройство.

## Проверки разработки

```bash
poetry run pytest -q
poetry run ruff check .
poetry run ruff format --check .
poetry run mypy
```

Тесты проверяют формат разметки, аудит, HTTP-контракт, ограничения загрузки,
EXIF-ориентацию и настройки. Они не скачивают веса; успешный ответ модели
в HTTP-тесте подменён. Реальный инференс и обучение требуют установленного
Ultralytics и весов и не подтверждены этими тестами.

Официальные источники: [YOLO26](https://docs.ultralytics.com/models/yolo26/),
[формат датасета](https://docs.ultralytics.com/datasets/detect/),
[предсказания](https://docs.ultralytics.com/modes/predict/),
[релиз Ultralytics](https://pypi.org/project/ultralytics/8.4.215/),
[Poetry](https://python-poetry.org/docs/basic-usage/),
[Pydantic Settings](https://docs.pydantic.dev/latest/concepts/pydantic_settings/).
